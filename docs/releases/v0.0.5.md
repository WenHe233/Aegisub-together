这是 Aegisub Together 的早期测试版本。协作协议仍为 v2，v0.0.5 Windows 客户端可以连接 v0.0.4 服务端；本次更新不修改服务端数据库结构，不需要迁移数据库。

本次更新重点：

- 修复协作锁等待、锁冲突或维护冻结期间，切换活动行后编辑框不显示对应文本的问题。程序刷新只更新显示，不会被误当作用户编辑提交。
- 恢复字幕网格类似电子表格的鼠标拖动多选：支持向上或向下连续选择、Ctrl 追加范围和 Shift 扩展范围，活动行始终跟随鼠标最后经过的行。
- 拖选期间不发送中间锁请求；松开鼠标或结束手势时只申请一次最终多行锁，避免锁状态抖动和迟到响应抢回焦点。
- Windows 客户端正式更名为 `Aegisub Together`，主程序改为 `aegisub-together.exe`，窗口、关于页、崩溃提示、版本资源和文件类型描述均使用新名称。
- 新安装使用独立 AppID 与 `AegisubTogether.*` 文件关联，可以与上游 Aegisub 并存。
- 用户配置与缓存改用 `%APPDATA%\Aegisub Together` 和 `%LOCALAPPDATA%\Aegisub Together`。本版本不会复制或移动旧 Aegisub 的配置、MRU、离线日志和缓存；已保存的协作密码仍沿用现有 Credential Manager 目标。
- portable 根目录和发布检查同步改为新名称，并确保发布包只包含 `aegisub-together.exe`，不包含旧 `aegisub.exe`。

虽然服务端无需因本版本升级，部署新服务端二进制或镜像前仍建议先备份 SQLite 数据库。公网仍应使用 `wss://`；`ws://` 只适合本机、隔离开发环境或可信局域网。部署前请阅读[协作服务端部署指南](https://github.com/WenHe233/Aegisub-together/blob/v0.0.5/docs/collaboration-deployment.md)。
