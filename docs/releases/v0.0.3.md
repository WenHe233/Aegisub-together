这是 Aegisub Together 的早期测试版本，重点修复 Windows 10 客户端在服务端已经接受建房或入房请求后仍立即断线的问题。它仍不建议用于无法承受数据损失的正式字幕项目。

本次更新重点：

- Windows 协作传输改用 WinHTTP 异步回调状态机，收发方向分别串行，并按连接 generation 丢弃旧连接迟到的回调和消息。
- 修复接收尚未完成时并发调用 `WinHttpWebSocketClose` 的生命周期竞态；主动停止会先发送 Shutdown，再按完成回调安全取消或关闭句柄。
- 传输失败现在会记录连接阶段、WinHTTP 操作、Windows 错误码与系统文本，以及 WebSocket Close 状态；诊断内容不会包含密码、字幕 payload 或 URL query。
- 首次建房或入房在收到 `room_joined` 前断线时不再自动重试，也不会重复发送非幂等的 `create_room`；客户端会提示房间可能已经创建，可改用“加入房间”。
- 修复客户端 JSON 解析器无法读取 Go 标准编码器产生的 `\uXXXX` 和 UTF-16 surrogate pair，确保大型压缩快照可以跨语言解码。
- Windows CI 新增真实传输烟雾测试：启动临时 Go 服务端和 SQLite，使用两个原生客户端完成访问认证、建房、入房、大型二进制快照、多分片接收、三次心跳和接收中的安全停止。
- 补齐协作连接、房间、行锁、维护模式、离线对账、批注与协作撤销/重做界面的简体中文翻译，并在发布流程中验证语言包已进入便携压缩包。
- 客户端正常断开或退出时会先发送 `leave_room`，服务端立即释放昵称、行锁、维护状态和恢复会话；异常掉线仍可使用 resume token 自动重连。

公网仍应使用 `wss://`；`ws://` 只适合本机、隔离开发环境或可信局域网。部署前请阅读[协作服务端部署指南](https://github.com/WenHe233/Aegisub-together/blob/v0.0.3/docs/collaboration-deployment.md)。
